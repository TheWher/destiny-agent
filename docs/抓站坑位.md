# 抓站坑位（crawl-pitfalls）

换站抓取前先翻这页。一条一坑三行：**现象 / 原因 / 对策**。抓新站（或老站新页面）踩坑后回来补，别只留在 commit 里。

---

## 1. ziweicn：http 被反爬拦截，https 直通

- **现象**：`http://www.ziweicn.com/...` 抓取失败，报 `Blocked by anti-bot protection: Structural: minimal_text, no_content_elements`（39 字节 0 字符可见）；移动站 `m.ziweicn.com` 同样被拦。
- **原因**：站点反爬只对 http 明文请求生效，https 不拦（实测 2026-08-11，天马星 3168 篇）。
- **对策**：ziweicn 的 ingest 配置 URL 一律用 `https://www.ziweicn.com/...`。已入库的 http 版本不必重洗（frontmatter fetched_at 保留原则）。

## 2. 噪音过滤正则：非 MULTILINE 模式下 `$` 匹配不到行尾

- **现象**：站点尾标/版权尾巴过滤规则 0 命中，污染文件残留。
- **原因**：Python `re.sub` 默认非 MULTILINE，`.*$` 的 `$` 只匹配字符串末尾，不匹配行尾。
- **对策**：行尾匹配用 `[^\n]*` 代替 `.*$`；加新源站噪音规则后在 ingest_batch 配置里测一遍命中再入库。

## 3. 新站抓取先配噪音过滤，再批量入库

- **现象**：ziweishuyuan 版权尾巴（"文章源自刘韫龄笔记…"每段重复）、微信号/公众号广告块、ziweicn 打赏广告（"【法布施得法！】…"）曾残留入库。
- **原因**：站点的模板尾巴/广告不属于正文，fit_markdown 修剪不彻底。
- **对策**：换新源站时先抓 1 篇人工检查正文污染，把规则写进 `scripts/ingest_noise_filters.json`（按域名配置），再批量跑；入库后 `--clean` 重洗存量（fetched_at 保留，加 cleaned_at 审计）。

## 4. frontmatter 卫生校验放源头（ingest 前置）

- **现象**：tags 曾出现代码残留、重复项，污染检索。
- **原因**：人工构造配置时误带入。
- **对策**：ingest_kb.py 内置 validate_frontmatter（必填字段/tags 去重/代码残留正则），不合格拦下不入库；改 frontmatter 或加素材后跑 `verify_kb_e2e.py --health`。

---

## 通用检查单（新站上线前）

1. 抓 1 篇 → 检查正文污染（版权尾巴/广告/导航残留）
2. 噪音规则写进 ingest_noise_filters.json → 再抓 1 篇确认命中
3. 配置 JSON：url（注意 http/https 反爬差异）/ title / source / authority / system（跨体系必填）/ tags
4. `--dry-run` 全批 → 正式入库
5. `sync_obsidian_to_kb.py` 同步项目仓副本 → `verify_kb_e2e.py --all`（health + regression）
6. 双仓推送（私有仓 vault 真源 → 项目仓派生副本）
