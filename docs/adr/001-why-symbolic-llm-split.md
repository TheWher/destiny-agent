# ADR-001: 为什么符号计算和 LLM 推理分两层

**日期**: 2026-07-29  
**状态**: 已采纳 (Accepted)

## 背景

八字排盘和紫微斗数排盘都需要精确的天文历法计算：节气时刻、干支转换、五行局定法。这些是确定性计算，不允许概率误差。

## 决策

分两层架构：
- **符号计算层** (`bazi_calculator.py`, `ziwei_calculator.py`)：确定性排盘，零幻觉要求
- **AI 推理层** (`services/`)：LLM 解释命盘，处理需要经验判断的模糊任务

两层通过 `plate_to_dict()` 输出的结构化 JSON 耦合。

## 代价

- 需要维护两套系统，增加代码量
- 符号层每次新增字段（如十二长生、飞星）需要同步更新 JSON 序列化
- LLM 不能自行推算，必须信任引擎输出，这限制了 Agent 的自主性

## 为什么不

- **让 LLM 直接算**：交叉验证发现 LLM 推算干支错误率 >30%，不可接受
- **全用符号计算**：格局判定、旺衰评估需要经验判断，规则穷举不完
