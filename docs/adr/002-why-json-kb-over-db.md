# ADR-002: 为什么知识库用 JSON 而非数据库

**日期**: 2026-07-29  
**状态**: 已采纳 (Accepted)

## 背景

项目知识库包含 14 个结构化文件：八字 9 个（调候表、十神映射、信号规则、格局判定、错误模式、术语、古籍引用等），紫微 5 个（星曜数据、宫位关系、格局条件等），总大小 ~120KB。

## 决策

使用 JSON 文件，运行时全量加载到内存缓存。

## 代价

- 每次分析时 146KB 全量拼接进 prompt，浪费 token
- 不支持语义检索，只能全量加载
- 没有版本控制粒度（改一个字就要整体替换）

## 为什么不

- **SQLite**：数据量 <200KB，SQL 查询带来的复杂度远大于收益。等知识库 >1MB 时重新评估
- **知识图谱**：命理知识的实体关系（星曜-宫位-格局）确实适合图结构，但当前知识量不足以支撑图的维护成本
- **向量数据库**：需要 embedding 服务，增加运维复杂度。当前关键词匹配已经够用

## 未来方向

当知识库增长到需要按需检索时，先实现关键词匹配检索（不改内容格式），再考虑向量检索。
