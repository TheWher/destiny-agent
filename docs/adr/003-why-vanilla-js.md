# ADR-003: 为什么前端零框架

**日期**: 2026-07-29  
**状态**: 已采纳 (Accepted)

## 背景

项目前端包含 4 个页面（Landing、八字输入、八字报告、紫微输入、紫微报告），主要交互是表单提交 + SSE 流式接收 + SVG 图表渲染 + 三层叠盘交互。

## 决策

使用原生 JavaScript + CSS Variables，不使用任何前端框架。

## 代价

- 复杂交互（如三层叠盘、三合四正连线 hover 高亮）用原生 JS 实现代码量较大
- 没有组件化，页头/导航栏在不同页面重复实现
- 移动端适配靠手写媒体查询，无法用响应式框架自动处理

## 为什么不

- **React/Vue**：项目页面数 <5，组件复用需求不大。引入框架意味着需要构建工具链（Webpack/Vite），增加 CI 复杂度和部署依赖
- **HTMX**：适合以服务端渲染为主的场景，但紫微的叠盘交互（多层级四化标记 + hover 连线高亮）需要细粒度 DOM 操作，HTMX 不够用
- **Alpine.js**：最接近"轻量"目标，但当前原生实现已经成熟，切换成本 > 收益

## 未来方向

如果前端页面增长到 10+ 或需要跨页面共享复杂组件（如命盘 Grid），重新评估 Alpine.js 或 Web Components。
