# 维护评估：iztro-py 0.3.5 → 0.5.0 升级评估（2026-09-09，韩湘生轮）

> 结论先行：**暂不升级，保持 `>=0.3.5,<0.4` 钉板**。0.4.0 起紫微安星年界改农历正月初一（主流口径），与本项目 year_gz 立春口径在每年 2-3 周窗口内分裂——这是口径级变更，须 King 拍板后再动。本评估 = 升级利弊 + 影响面 + 两套方案的完整清单。

## 一、升级收益（真实且重大）

0.4.0（2026-07-18）/ 0.5.0（2026-07-25）修复的上游正确性 bug，多个打在本项目核心域：

| 上游修复 | 对本项目影响 |
|---|---|
| **亮度表重写**（0.4.0：「除紫微外主星亮度几乎全错」，按 iztro STARS_INFO 重写，六吉火铃羊陀全扩） | 引擎 `_brightness()` 驱动日月并明/月朗天门等全部庙旺条件格局。项目有自己的 `_BRIGHTNESS_FIX`（令东来表，5级→7级）覆盖输出——部分对冲，但 iztro 原始值错则修正表输入即错 |
| **年/月柱切分 立春→农历正月初一**（0.4.0：立春切分「导致春节后至立春前出生的盘完全错误」） | 见第三节——**升级的核心阻塞点** |
| **虚岁改按农历年**（0.4.0：原公历年「使大限/小限偏移一年」） | `decadal_range`（大限岁段）可能错一年；三方互证当年抽的盘未必落在分歧窗口 |
| **日柱锚点偏差 51 天修复**（0.5.0：「日柱全错，567 日抽检全部不匹配」） | 若 `get_day_stem_branch` 被用到则严重；本项目日柱走 bazi_calculator，待核 iztro 侧引用 |
| 早/晚子时区分、decadal index -1 哨兵、跨语言污染等 | 影响面小（见第二节） |

## 二、破坏面 vs 本项目使用面（实测核对）

项目只消费：`by_solar/by_lunar('zh-CN')`、`chart.palaces`、`get_soul/body_palace()`、`chart.horoscope(f"{Y}-03-01", 0)`、`decadal.{range,heavenly_stem,earthly_branch,index}`、`s.brightness`、`chart.five_elements_class`。**不碰** fix_leap / solar_to_lunar / en-US / astrolabe.time/zodiac / 已删 7 个内部 API。

- 实测升级 0.5.0 后全量回归 **159 中仅 1 红**（见第三节），API 层无 breaking 命中
- decadal index -1 哨兵：项目三处消费点均有 `0 <= idx < 12` 守卫 ✓
- 五行局 zh-CN 默认不受本地化影响 ✓

## 三、核心阻塞：紫微安星年界口径分裂（King 拍板件）

**现状（0.3.5）**：iztro 按立春切年 → 图表宫干（五虎遁）与项目 `year_gz`（bazi calc_sizhu，立春界）**全域一致**。

**0.4.0 起**：iztro 按农历正月初一切年（主流排盘软件口径）→ 在「立春后~春节前」窗口（每年 0~3 周，如 2026-02-04~16）**宫干按旧年干、year_gz 显示新同年干**：

实测样本 2005-02-06 00:30 男（验证尺巳酉变体盘）：
- 0.3.5：乙酉盘，命丑天梁+太阳巳旺+太阴酉旺 → 日月并明命中（尺子期望，2026-08-05 锁）
- 0.5.0：**安星整盘位移**——命丑天府、太阳子陷、太阴寅陷 → 日月并明判无（回归唯一红）
- 且该盘 `year_gz=乙酉`（立春口径）vs 宫干丙寅起（甲年五虎遁=农历甲申口径）→ **同盘两套年干，生年四化与显示年干互相矛盾**

**连带的深层问题**：验证尺「真乙酉年盘」的选盘逻辑本身是立春口径——按紫微主流（农历界）该盘是甲申年腊月生，「辛乙生人合格」前提不成立。若拍板安星切农历，**不止引擎，尺子/词典/注入用例的年界标注都要按新口径复核**。

### 两个方案的完整代价

**方案 A：保持 0.3.5（现状，零成本）**
- 挂账项：亮度表上游重写（项目 `_BRIGHTNESS_FIX` 部分对冲）、虚岁大限偏移、日柱修复全部不享
- 风险：上游 0.4/0.5 已成主流，0.3.x 不再维护；Python 新版本兼容性风险随时间上升

**方案 B：升 0.5.0 + 全链口径对齐（拍板后一个完整战役）**
1. King 拍板紫微安星年界 = 农历正月初一（主流）或立春（与八字统一）
2. 若拍农历：`year_gz` 拆双口径字段——`year_gz_bazi`（立春，八字/来因宫用）+ `year_gz_ziwei`（农历，安星/生年四化用）；前端来因宫锚位表、盘指纹、prompt 注入段全部跟着改
3. 尺子重校：verify_geju_mingzhu / verify_laiyin / check_rm_pans 的年界期望值逐盘复核（引擎实测锚定，禁人脑推导）
4. 亮度表重做对照：`_BRIGHTNESS_FIX`（令东来）vs iztro 0.5 新表逐星比对，差异处翻书证（obsidian 亮度口径对照笔记是现成底稿）
5. 大限虚岁窗口抽真盘三方互证
6. 全量回归 + LLM 注入用例重跑（docs/geju_diff 全套对比）
